# AI 使用与验证记录

日期：2026-10-10，Asia/Shanghai。

## AI 参与范围

Codex 参与题目拆解、产品范围选择、数据模型、运行器、前端界面、测试和文档实现。候选人的选题与数据库／部署选择来自用户：投资 X Buddy、MySQL、本地运行、Docker Compose，之后明确要求公网部署并选择 Railway。

本项目默认运行中不调用付费模型：规则规划与构造数据模式均明确标注。配置真实模型后，模型参与计划、解释和追问；算式、权限和持久化不由模型控制。

公网上线由 Codex 辅助创建公开源码仓库、配置并发布 Railway 应用与 MySQL。用户本人完成平台登录，并分别明确批准官方 CLI 的权限和临时部署 SSH 公钥。临时公钥在应用专用数据库账号配置后撤销。公网验收使用实际 HTTPS 接口、实际云端重启和浏览器操作，不用本机结果代替公网结果。

第二版按用户确认的六项方案逐项修改。Codex 使用 TDD 公开合约验收和 agent-browser 本机操作验证，先保留原版源码与数据库一致性副本。最终源代码、验收和文档由 AI 辅助实现，不能把这些工作描述为完全独立手写。

## 第二版发现与修正

| 发现                                   | 修正                                     | 实际验证                                          |
| -------------------------------------- | ---------------------------------------- | ------------------------------------------------- |
| 初始拒绝与旧版本可能通过不同入口执行   | 统一授权，并在预占后再次核验当前版本     | retry/resume拒绝、旧版本和请求发起竞态测试        |
| 聚合写入失败可能漏记费用，并发可能透支 | 独立事务账本，稳定请求键，开始／结算分开 | 本机供应商请求计数；SIGKILL后费用保留；重复键拒绝 |
| 缺少凭据被误计为外部尝试               | 凭据预检放在请求预占与发起前             | 没有 transport 请求且账本为空                     |
| 缺字段任务状态 done，重试不补数        | 根据指标依赖识别必须重取任务             | 缺字段恢复完成；收入研究不依赖现金流              |
| 标准文字仅凭关键词可能被误认为完成     | 只编译已注册明确模板，其他保持未达成     | 自定义阈值和未接入字段保持 partial                |
| 稳定字段 ID 在刷新后混淆原值           | 内容身份、不可变表和独立历史读取         | 新身份／旧值测试，历史和owner隔离                 |
| MySQL 二进制JSON重编码一个浮点结果末位 | 项目与证据使用精确 JSON 文本封装         | 初次实际MySQL复算失败；修复后8条算式全部通过      |
| 模板风险提醒不能解释材料如何改变判断   | 定向核查、逐字定位、四类关系和判断修订   | 限制材料收窄假设，无关材料不挂反证                |
| 中文数字可能绕过仅阿拉伯数字检查       | 补中文金额／比例和确定性表达检查         | 无依据中文金额与确定性结论被移除                  |
| 全部检索候选引用被当作模型实际引用     | 保存实际返回并通过白名单的ID             | 模型返回一条，消息仅保存一条                      |
| 最近回答和用户纠正没有进入模型输入     | 语义摘要与近期对话，纠正保持未验证       | 实际协议请求包含纠正和近期助手回答                |
| 证据身份改变后前端表仍按旧 ID 找值     | 按实体／期间／字段选择当前证据           | 浏览器显示指标和变化率且可逐层点击                |
| 新反证说明文字对比度不足               | 调整说明文字颜色                         | 重新构建并复查axe结果                             |

最终测试47/47通过；实际MySQL与独立复算记录见outputs。视频为128秒左右无声实际浏览器录制，不表示真实模型或真实财报在线运行。

## 实际验证与修正

| 发现                                     | 修正                                    | 验证                              |
| ---------------------------------------- | --------------------------------------- | --------------------------------- |
| 沙箱阻止本机接口测试连接                 | 使用获准的本机测试执行环境              | 接口测试能够访问独立测试服务      |
| 异常退出后旧 Worker 租约使恢复等待过长   | 默认租约15秒并定期续租；测试使用1秒租约 | 真实进程重启后恢复并复用完成任务  |
| MySQL JSON 重排导致审批哈希不同          | 对计划和预算做稳定按键序列化            | MySQL 主链路与哈希顺序回归测试    |
| UTC 日期截断可能提前使用北京时间次日公告 | 以 Asia/Shanghai 比较公开日期           | 边界测试拒绝 UTC16点对应次日数据  |
| 财务数据不能只看 HTTP 状态               | 检查扶摇业务 code                       | HTTP200、code2003 被识别为失败    |
| 净利润分母可能非正                       | 不生成普通比值／增长率，保留说明        | 零和负分母测试不产生 Infinity/NaN |
| 改计划后旧证据不能冒充新范围成果         | 保存历史快照，新版重新建立证据          | 旧审批拒绝、新计划版本保留历史    |
| 初始浅色文字可读性不足                   | 加大文字、提高对比度、移除外部字体依赖  | 浏览器可访问性检查与截图审阅      |
| 扩展预算可能绕过已失败的对象核对         | 执行器再次检查对象核对状态              | 独立回归测试验证无后续财务调用    |
| 工具标题与证据弹层的语义不合适           | 修正标题级别与对话框元素                | 浏览器自动可访问性检查            |

## 可核实程度

自动验证包括字段映射、计算、引用存在、时间口径、状态、审批和恢复。它不证明金融因果解释正确。反证检索没有全覆盖保证，用户需要审阅局限。

没有提供真实模型或扶摇凭据，因此不能在记录中宣称已验证供应商线上调用。本机 Docker Compose 编排仍待有 Docker 的环境验证；Railway 云端 Dockerfile 构建、容器运行及 MySQL 9.7.2 已实际验收。
